# Setup and building ROMs (v1.1.1)

## Launching the editor

**Windows:** Install Python 3 with Tkinter, run `py -3 -m pip install -r requirements.txt`, then launch `Run_NovaDS.bat` from the repository root. Alternatively run `py -3 run_editor.py`.

**Other desktops:** Tkinter + Pillow are required. Run `python3 -m pip install -r requirements.txt` and `python3 run_editor.py`. Windows is the primary tested development host.

The editor previews scene layout but is **not** a DS emulator: physics and Lua gameplay only run in exported ROMs.

## Installing the Nintendo DS toolchain

Install devkitPro with **devkitARM**, **libnds** and Nintendo DS build tools, using the [official installation instructions](https://devkitpro.org/wiki/Getting_Started). On Windows this normally provides the devkitPro MSYS2 shell. Set `DEVKITPRO` and `DEVKITARM` correctly if your installation is nonstandard.

## Exporting and compiling

1. Start NovaDS and open an example project, or create and save one.
2. Choose **File → Export Sources…** (or **File → Build .nds ROM** to attempt the build from the editor).
3. Open devkitPro MSYS2 and change to that exported source directory (for example `cd /c/Users/YourName/Projects/MyGame`).
4. Run `make` and wait for `NovaDS_Game.nds`.
5. Test the ROM with melonDS and, where possible, on a real DS/DS Lite with an appropriate homebrew loader.

### Lua dependency

The exporter includes `setup_lua.py`, which downloads the official Lua **5.4.9** source archive, verifies SHA-256 and prepares the minimal Lua VM sources that are compiled into the ROM. Lua is downloaded during export/build preparation, **not** pulled from an untrusted GitHub mirror. Lua's own [license](https://www.lua.org/license.html) applies to Lua itself.

If MSYS2 Python is unavailable, use Windows Python to run `py -3 setup_lua.py` in the exported directory *before* `make`. When using the editor's Build ROM command, the editor prepares Lua via the host Python automatically. Alternatively place the official `lua-5.4.9.tar.gz` beside the generated `setup_lua.py` and run it locally.

### Known build problems

**`Could not open 'icon.bmp'`:** v1.1.1 fixes a relative icon-path bug. Re-export using this release; if working from an older v1.1 export, use the v1.1.1 Makefile fix so `GAME_ICON` resolves from the exported project's root.

**No `DEVKITARM`:** Open the correct devkitPro shell / set `DEVKITPRO` and `DEVKITARM` and verify `make` and the ARM compiler are on PATH.

**Lua header not found:** Re-run the exported `setup_lua.py`; verify the official archive and downloaded source tree are complete.

**No executable from `make`:** Do not run make solely on the Lua prep target; the top-level default goal must be `all`. New exports generated by v1.1.1 do this.

For additional diagnostics see [v1.0 troubleshooting chapter](manual_v1.0/markdown/06_BUILD_TROUBLESHOOTING.md), the [v1.1 source notes](DUAL_3D_AND_BANNER.md), and `example_export_dual3d/HOW_TO_BUILD.txt`.
